# JVM 类加载机制详解

> 本文档详细讲解 JVM 类加载的完整流程、双亲委派模型、自定义类加载器等核心知识

## 1. 类加载概述

### 1.1 什么是类加载？

将类的 `.class` 文件中的二进制数据读取到内存中，将其转化为方法区的运行时数据结构，然后在堆中生成一个 `java.lang.Class` 对象，作为方法区数据的访问入口。

## 2. 类加载过程详解

### 2.1 加载（Loading）

#### 完成内容

1. **通过类的全限定名获取类的二进制字节流**
2. **将字节流转化为方法区的运行时数据结构**
3. **在堆中生成 `java.lang.Class` 对象**

#### 加载来源

| 来源 | 说明 |
|------|------|
| 本地文件系统 | 从 classpath 加载 |
| 网络 | Applet |
| 数据库 | 某些企业级应用 |
| 动态生成 | 动态代理、反射 |
| ZIP/JAR 文件 | 从 jar 包加载 |
| 其他文件 | 从 JSP 生成的 class 文件 |

#### 数组类的加载

- 数组类本身不通过类加载器创建
- 由 JVM 直接创建
- 但数组类的元素类型需要类加载器加载

### 2.2 验证（Verification）

#### 目的

确保 Class 文件的字节流符合 JVM 规范，不会危害虚拟机安全。

#### 验证阶段

```
┌─────────────────────────────────────────────────────────────────┐
│                      验证阶段                                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌─────────────┐                                               │
│  │ 1. 文件格式验证 │  - 魔数、版本号、常量池等                  │
│  └──────┬──────┘                                               │
│         │                                                       │
│         ▼                                                       │
│  ┌─────────────┐                                               │
│  │ 2. 元数据验证 │  - 语义分析、字节码语义                     │
│  └──────┬──────┘                                               │
│         │                                                       │
│         ▼                                                       │
│  ┌─────────────┐                                               │
│  │ 3. 字节码验证 │  - 数据流、控制流分析                       │
│  └──────┬──────┘                                               │
│         │                                                       │
│         ▼                                                       │
│  ┌─────────────┐                                               │
│  │ 4. 符号引用验证│ - 解析阶段检查能否正确引用                   │
│  └─────────────┘                                               │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**详细说明：**

| 验证阶段 | 验证内容 |
|----------|----------|
| 文件格式验证 | 魔数（0xCAFEBABE）、版本号、常量池类型 |
| 元数据验证 | 是否有父类、是否继承了 final 类、抽象方法是否实现 |
| 字节码验证 | 数据栈、操作数栈是否溢出、类型转换是否有效 |
| 符号引用验证 | 能否通过全限定名找到对应类、字段/方法访问权限是否合法 |

### 2.3 准备（Preparation）

#### 目的

为类变量（static 修饰的变量）分配内存并设置初始值。

#### 关键点

- **分配内存**：在方法区中分配
- **初始值**：零值（0, null, false 等），而非代码中的初始值

```
┌─────────────────────────────────────────────────────────────────┐
│                      准备阶段                                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  public class Demo {                                           │
│      // 类变量（static），在准备阶段分配内存                     │
│      public static int value = 123;    // 初始值 = 0，不是123   │
│      public static final int CONST = 123; // 常量，准备阶段=123 │
│  }                                                              │
│                                                                 │
│  说明：                                                         │
│  - static 变量：在准备阶段分配内存，初始值为零值                 │
│  - static final 常量：在准备阶段直接赋值（编译期常量）          │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### 基本数据类型的零值

| 数据类型 | 零值 |
|----------|------|
| int、short、byte、long | 0 |
| float、double | 0.0 |
| char | '\u0000' |
| boolean | false |
| reference | null |

### 2.4 解析（Resolution）

#### 目的

将常量池中的符号引用替换为直接引用。

#### 符号引用 vs 直接引用

| 概念 | 说明 |
|------|------|
| 符号引用 | 用一组符号描述所引用的目标，与内存布局无关 |
| 直接引用 | 指向目标的指针、相对偏移量，能直接定位目标 |

#### 解析的类/接口

| 类型 | 说明 |
|------|------|
| 类/接口解析 | 判断是否可以访问（权限检查） |
| 字段解析 | 从父类/接口/本类逐层查找 |
| 方法解析 | 从父类/接口逐层查找 |
| 接口方法解析 | 从父接口逐层查找 |

#### 解析时机

- JVM 规范不强制要求在类加载时就完成解析
- 大多数 JVM 在类加载时进行解析
- 某些场景下（动态绑定），解析会延迟到首次使用时

### 2.5 初始化（Initialization）

#### 目的

执行类构造器 `<clinit>()` 方法，为类变量赋予代码中定义的初始值。

#### `<clinit>()` vs `<init>()`

| 构造器 | 说明 |
|--------|------|
| `<clinit>()` | 类构造器，static 变量的赋值语句和 static 块 |
| `<init>()` | 实例构造器，构造函数 |

#### 执行时机（主动引用）

触发初始化的6种情况：

1. **new**、**getstatic**、**putstatic**、**invokestatic** 字节码指令
2. **反射**调用：`Class.forName()`
3. **子类初始化**时，父类必须先初始化
4. **启动类**（main 方法所在类）
5. **MethodHandle** 解析结果为 `REF_getStatic` 等的方法

#### 不触发初始化（被动引用）

```java
// 被动引用示例

// 1. 通过子类引用父类的 static 字段，不会触发子类初始化
System.out.println(SubClass.value);  // 触发父类初始化，不触发子类

// 2. 引用数组类型，不触发类初始化
Demo[] array = new Demo[10];  // 不会触发 Demo 初始化

// 3. 引用常量（编译期确定），不会触发类初始化
System.out.println(CONSTANT);  // 常量在编译阶段放入常量池

// 4. ClassLoader 加载类，不触发初始化
Class<?> clazz = Class.forName("com.demo.Demo", false, loader);  // 第二个参数为 false
```

## 3. 类加载器

### 3.1 类加载器分类

```
┌─────────────────────────────────────────────────────────────────┐
│                      类加载器层次结构                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │

│                         ↑                                       │
│                    ↑                                           │
```

| 加载器 | 加载路径 | 说明 |
|--------|----------|------|
| Bootstrap ClassLoader | `$JAVA_HOME/lib` | 加载核心类库（rt.jar、tools.jar），安全目录 |

| App ClassLoader | `classpath` | 加载应用程序类 |

### 3.3 双亲委派模型

#### 原理

```
┌─────────────────────────────────────────────────────────────────┐
│                      双亲委派模型                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│         ┌─────────────────┐                                      │
│         │  Bootstrap     │  ← 最高层                            │
│         │  ClassLoader   │                                      │
│         └────────┬────────┘                                      │
│                  │                                              │
│         ┌────────┴────────┐                                      │
│         │  Extension      │                                      │
│         │  ClassLoader    │                                      │
│         └────────┬────────┘                                      │
│                  │                                              │
│         ┌────────┴────────┐                                      │
│         │     App         │                                      │
│         │  ClassLoader    │                                      │
│         └────────┬────────┘                                      │
│                  │                                              │
│         ┌────────┴────────┐                                      │
│         │     自定义      │                                      │
│         │  ClassLoader    │  ← 最底层                            │
│         └─────────────────┘                                      │
│                                                                 │
│  工作流程：                                                     │
│  1. 类加载请求向上传递，直到 Bootstrap                          │
│  2. Bootstrap 无法加载时，委派给 Extension                      │
│  3. Extension 无法加载时，委派给 App                           4. App 无法加载时，由 │
│  自定义加载器加载                           │
│                                                                 │
│  核心逻辑在 ClassLoader 的 loadClass() 方法中                   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### 代码实现

```java
protected Class<?> loadClass(String name, boolean resolve) {
    synchronized (getClassLoadingLock(name)) {
        // 1. 检查是否已经加载
        Class<?> c = findLoadedClass(name);
        if (c == null) {
            try {
                // 2. 委派给父类加载器
                if (parent != null) {
                    c = parent.loadClass(name, false);
                } else {
                    // 3. 父类为空，尝试 Bootstrap
                    c = findBootstrapClassOrNull(name);
                }
            } catch (ClassNotFoundException e) {
                // 父类无法加载
            }

            // 4. 父类无法加载，自己加载
            if (c == null) {
                c = findClass(name);
            }
        }

        if (resolve) {
            resolveClass(c);
        }
        return c;
    }
}
```

#### 双亲委派优点

| 优点 | 说明 |
|------|------|
| **安全性** | 避免核心类被篡改（如自定义 String 类无效） |
| **避免重复加载** | 父类已加载，子类无需重复加载 |
| **类的层次性** | 保证类的唯一性和正确性 |

## 4. 打破双亲委派模型

### 4.1 为什么要打破？

某些场景需要打破双亲委派：
- **Tomcat**：多个 Web 应用可能使用相同类名的不同版本
- **JDBC**：驱动由各厂商实现，需要由 App ClassLoader 加载
- **OSGi**：模块化加载
- **热部署**：应用运行时重新加载类

### 4.2 打破方式

#### 写 load方式一：重Class() 方法

```java
public class MyClassLoader extends ClassLoader {
    @Override
    protected Class<?> loadClass(String name, boolean resolve)
            throws ClassNotFoundException {

        // 自定义加载逻辑：自己加载，不委派
        if (name.startsWith("com.myapp.")) {
            return findClass(name);
        }

        // 其他类走双亲委派
        return super.loadClass(name, resolve);
    }
}
```

#### 方式二：线程上下文类加载器

```java
// JDK SPI 使用这种方式
// 例如：JDBC 驱动加载

// 1. 获取线程上下文类加载器
ClassLoader tccl = Thread.currentThread().getContextClassLoader();

// 2. 使用上下文类加载器加载
Class.forName("com.mysql.jdbc.Driver", true, tccl);
```

## 5. 自定义类加载器

### 5.1 应用场景

| 场景 | 说明 |
|------|------|
| **热部署** | 应用运行时动态加载/卸载类 |
| **加密保护** | 加载自定义加密的 class 文件 |
| **动态生成** | 运行时动态生成字节码 |
| **隔离加载** | 同一个 JVM 中运行多个版本相同类 |
| **非标准来源** | 从网络、数据库加载类 |

### 5.2 实现步骤

```java
import java.io.*;

public class MyClassLoader extends ClassLoader {

    private String classPath;

    public MyClassLoader(String classPath) {
        this.classPath = classPath;
    }

    @Override
    protected Class<?> findClass(String name) throws ClassNotFoundException {
        try {
            // 读取 class 文件为字节数组
            byte[] classData = getData(name);
            if (classData == null) {
                throw new ClassNotFoundException(name);
            }
            // 调用 defineClass 将字节数组转换为 Class 对象
            return defineClass(name, classData, 0, classData.length);
        } catch (IOException e) {
            throw new ClassNotFoundException(name, e);
        }
    }

    private byte[] getData(String className) throws IOException {
        String path = classPath + File.separator +
            className.replace('.', File.separatorChar) + ".class";
        FileInputStream fis = new FileInputStream(path);
        ByteArrayOutputStream baos = new ByteArrayOutputStream();
        byte[] buffer = new byte[4096];
        int len;
        while ((len = fis.read(buffer)) != -1) {
            baos.write(buffer, 0, len);
        }
        fis.close();
        return baos.toByteArray();
    }

    public static void main(String[] args) throws Exception {
        // 使用自定义类加载器
        MyClassLoader loader = new MyClassLoader("D:/classes");
        Class<?> clazz = loader.loadClass("com.demo.Hello");
        Object obj = clazz.newInstance();
        clazz.getMethod("say").invoke(obj);
    }
}
```

## 6. Tomcat 类加载器架构

### 6.1 Tomcat 为什么需要打破双亲委派？

- 同一个 Web 应用中可能有多个版本的相同类（如不同版本的 Spring）
- 同一个 JVM 中运行多个 Web 应用，需要隔离

### 6.2 Tomcat 类加载器结构

```
┌─────────────────────────────────────────────────────────────────┐
│                    Tomcat 类加载器架构                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│              Bootstrap ClassLoader                             │
│                    ↑                                           │
│              System ClassLoader                                │
│                    ↑                                           │
│              Common ClassLoader                                │
│          ┌───────────────┬───────────────┐                     │
│          │               │               │                     │
│     ┌────┴────┐    ┌────┴────┐    ┌────┴────┐                  │
│     │ Webapp1 │    │ Webapp2 │    │ Webapp3 │  ← 每个 Web 应用  │
│     │ Class-  │    │ Class-  │    │ Class-  │    独立的加载器    │
│     │ Loader │    │ Loader  │    │ Loader  │                  │
│     └─────────┘    └─────────┘    └─────────┘                  │
│                                                                 │
│  加载顺序：                                                     │
│  1. Bootstrap → System → Common → Webapp                        │
│  2. Webapp 先尝试自己加载，不委派                               │

│                                                                 │

```

## 7. 常见面试问题汇总

### 问题与答案

| 问题 | 答案 |
|------|------|
| 类加载过程？ | 加载→验证→准备→解析→初始化 |
| 验证阶段验证什么？ | 文件格式、元数据、字节码、符号引用 |
| 准备阶段做什么？ | 为 static 变量分配内存，设置零值 |
| 解析阶段做什么？ | 符号引用转换为直接引用 |
| 初始化阶段做什么？ | 执行 `<clinit>` 方法，赋予代码中的初始值 |
| 类加载器有哪些？ | Bootstrap、Extension、App、自定义 |
| 双亲委派模型？ | 父类加载器先尝试加载，失败才交给子类 |
| 双亲委派优点？ | 避免类重复加载、安全性 |
| 打破双亲委派的方式？ | 重写 loadClass()、线程上下文类加载器 |
| 何时触发类初始化？ | new、静态字段/方法、反射、main 类 |
| 被动引用不触发初始化？ | 引用常量、子类引用父类 static、数组类型 |

### 深入问题

> **Q：为什么数组类型不需要类加载器加载？**
>
> A：数组类型由 JVM 在运行期间动态生成，不存储在 .class 文件中。数组的元素类型需要类加载器加载。

> **Q：`<clinit>` 方法和 `<init>` 方法的区别？**
>
> A：`<clinit>` 是类构造器，由 static 变量赋值和 static 块组成；`<init>` 是实例构造器，由构造函数组成。

> **Q：Class.forName() 和 ClassLoader.loadClass() 的区别？**
>
> A：`Class.forName()` 加载类后会执行初始化（默认 initialize=true）；`ClassLoader.loadClass()` 只加载不初始化。

## 8. 总结

### 类加载流程图

```
┌─────────────────────────────────────────────────────────────────┐
│                    类加载完整流程                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 加载                                                       │
│     - 获取二进制字节流                                          │

│                                                                 │
│  3. 准备                                                       │

```

### 核心要点

1. **加载是类加载的第一步**，验证、准备、解析是连接阶段
2. **准备阶段设置零值**，初始化阶段才赋予真正初始值
3. **双亲委派模型**保证安全性和唯一性
4. **自定义类加载器**需要继承 ClassLoader 并重写 findClass()
5. **打破双亲委派**是为了满足特殊场景需求
