# JVM 内存结构（运行时数据区）详解

> 本文档详细讲解 JVM 运行时数据区的各个组成部分，是理解 JVM 的基础

## 1. 整体架构概览

Java 虚拟机在执行 Java 程序时会把它所管理的内存划分为若干个不同的数据区域。这些区域各有各自的用途，以及创建和销毁的时间。

```
┌─────────────────────────────────────────────────────────────────┐
│                        JVM 进程内存                              │
├─────────────────────────────────────────────────────────────────┤
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                    线程共享区域                          │   │
│  │  ┌─────────────────────┐  ┌──────────────────────────┐  │   │
│  │  │        堆           │  │        方法区            │  │   │
│  │  │   (Heap)            │  │   (Method Area)          │  │   │
│  │  │                     │  │                          │  │   │
│  │  │  对象实例、数组     │  │  类信息、常量、静态变量   │  │   │
│  │  │                     │  │  JIT编译产物             │  │   │
│  │  └─────────────────────┘  └──────────────────────────┘  │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                    线程私有区域                          │   │
│  │  ┌─────────────────┐  ┌─────────────────┐  ┌─────────┐  │   │
│  │  │  程序计数器    │  │   虚拟机栈      │  │本地方法栈│  │   │
│  │  │ (PC Register)  │  │ (VM Stack)      │  │(Native) │  │   │
│  │  │                 │  │                 │  │         │  │   │
│  │  │  字节码行号    │  │  方法栈帧       │  │Native   │  │   │
│  │  │  指示器        │  │  局部变量表     │  │方法服务  │  │   │
│  │  └─────────────────┘  └─────────────────┘  └─────────┘  │   │
│  └─────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────┘
```

## 2. 程序计数器（Program Counter Register）

### 2.1 定义

程序计数器（Program Counter Register）是一块较小的内存空间，它可以看作是**当前线程所执行的字节码的行号指示器**。

### 2.2 作用

- 字节码解释器通过改变程序计数器的值来选取下一条需要执行的字节码指令
- 分支、循环、跳转、异常处理、线程恢复等基础功能都依赖程序计数器

### 2.3 特点

| 特性 | 说明 |
|------|------|
| 线程私有 | 每个线程都有独立的程序计数器 |
| 内存区域 | 唯一没有 OutOfMemoryError 的区域 |
| 存储内容 | 正在执行的字节码行号；若执行 Native 方法，则为空（undefined） |

### 2.4 为什么需要线程私有？

Java 虚拟机的多线程是通过**线程轮流切换、分配处理器执行时间**的方式实现的。在任意一个确定的时刻，一个处理器（对于多核处理器来说是一个内核）只会执行一条线程中的指令。

为了能够准确地记录各个线程正在执行的字节码位置，每个线程都需要有一个独立的程序计数器，各条线程之间计数器互不影响，独立存储。

### 2.5 面试提问

> **Q：为什么程序计数器是线程私有的？**
>
> A：因为CPU会在线程之间切换，每个线程需要独立记录自己执行到了哪里。如果不私有，多个线程共享一个计数器，当线程切换时就会丢失自己的执行位置。

## 3. Java 虚拟机栈（Java Virtual Machine Stack）

### 3.1 定义

Java 虚拟机栈（Java Virtual Machine Stack）也是线程私有的，它的生命周期与线程相同。

虚拟机栈描述的是 **Java 方法执行的线程内存模型**：每个方法被执行的时候，Java 虚拟机都会同步创建一个**栈帧（Stack Frame）**用于存储局部变量表、操作数栈、动态连接、方法出口等信息。

### 3.2 栈帧结构

```
┌─────────────────────────────────┐
│         栈帧（Stack Frame）      │
├─────────────────────────────────┤
│  局部变量表 (Local Variables)   │  ← 存放方法参数和局部变量
├─────────────────────────────────┤
│  操作数栈 (Operand Stack)       │  ← 存放操作数
├─────────────────────────────────┤
│  动态链接 (Dynamic Linking)    │  ← 指向运行时常量池的方法引用
├─────────────────────────────────┤
│  方法返回地址 (Return Address)   │  ← 方法退出后继续执行的地址
└─────────────────────────────────┘
```

### 3.3 局部变量表

- 存放方法参数和局部变量
- 基本数据类型（boolean, byte, char, short, int, long, float, double）
- 对象引用（reference）
- returnAddress（返回地址）
- 容量以**变量槽（Slot）**为单位，64位长度的 long 和 double 占用2个槽，其余占用1个槽

### 3.4 操作数栈

- 后进先出（LIFO）栈
- 用于存放方法执行过程中的中间值
- 字节码指令从操作数栈中弹出操作数，计算后再压回操作数栈

### 3.5 动态连接

- 每个栈帧都包含一个指向**运行时常量池**中该栈帧所属方法的引用
- 目的是为了支持方法调用过程中的**动态链接**

### 3.6 常见异常

| 异常类型 | 原因 |
|----------|------|
| StackOverflowError | 线程请求的栈深度大于 JVM 所允许的最大深度（通常是因为递归调用过深） |
| OutOfMemoryError | 栈内存无法动态扩展时抛出（JVM 可以选择固定栈大小） |

### 3.7 面试提问

> **Q：虚拟机栈和本地方法栈有什么区别？**
>
> A：虚拟机栈为 Java 方法（字节码）服务，本地方法栈为 Native 方法服务。在 HotSpot JVM 中，将两者合二为一，使用相同的内存区域。

> **Q：方法局部变量线程安全吗？**
>
> A：如果局部变量是基本数据类型，存在栈帧中，线程私有，绝对安全；如果局部变量是对象引用，需要考虑对象的线程安全性（对象本身可能共享）。

## 4. 本地方法栈（Native Method Stack）

### 4.1 定义

本地方法栈（Native Method Stack）与虚拟机栈所发挥的作用非常相似，区别是：
- 虚拟机栈为 Java 方法（字节码）服务
- 本地方法栈为 **Native 方法**（使用 native 关键字修饰的方法）服务

### 4.2 实现

- 在 HotSpot JVM 中，**本地方法栈和虚拟机栈合二为一**
- 不使用 native 方法的开发者可能感受不到它的存在
- 但对于需要调用 C/C++ 本地库的框架（如JNI、JNA）非常重要

### 4.3 常见异常

与虚拟机栈相同：
- StackOverflowError：栈深度溢出
- OutOfMemoryError：栈内存溢出

## 5. 堆（Heap）

### 5.1 定义

**堆是 JVM 所管理的内存中最大的一块**，被所有线程共享，在虚拟机启动时创建。

堆的唯一目的就是**存放对象实例和数组**（几乎所有的对象实例都在这里分配内存）。

### 5.2 内存划分

现代垃圾收集器基于**分代收集理论**，将堆划分为：

```
┌────────────────────────────────────────────────────────┐
│                      堆内存                            │
├────────────────────────────────────────────────────────┤
│                                                        │
│  ┌──────────────────────────────┬───────────────────┐│
│  │         新生代 (Young Gen)    │   老年代          ││
│  │                              │   (Old Gen)       ││
│  │  ┌─────────┬─────────┬─────┐ │                   ││
│  │  │ Eden    │Survivor│Surv │ │                   ││
│  │  │         │  To    │From │ │                   ││
│  │  └─────────┴─────────┴─────┘ │                   ││
│  │       8:1:1                   │                   ││
│  └──────────────────────────────┴───────────────────┘│
│                                                        │
│  比例：-XX:NewRatio=2 表示 老年代:新生代 = 2:1        │
└────────────────────────────────────────────────────────┘
```

### 5.3 新生代与老年代

| 区域 | 比例 | 存储内容 | 垃圾回收频率 |
|------|------|----------|--------------|
| 新生代 | 1/3 堆 | 新创建的对象 | 频繁 |
| 老年代 | 2/3 堆 | 长生命周期对象 | 较少 |

### 5.4 新生代细分

| 区域 | 比例 | 说明 |
|------|------|------|
| Eden 区 | 80% | 新对象分配区域 |
| Survivor From | 10% | 复制算法的from区 |
| Survivor To | 10% | 复制算法的to区（交换后变为From区） |

### 5.5 常见异常

- **OutOfMemoryError: Java heap space**：堆内存不足，无法分配对象

### 5.6 面试提问

> **Q：为什么堆需要分代？不分代可以吗？**
>
> A：研究表明，大部分对象都是朝生夕死的，少部分对象会长期存活。分代后，可以针对不同代采用不同的垃圾回收算法，提高效率。不分代也可以（ZGC、Shenandoah 就是不分代的收集器），但分代是主流优化方案。

## 6. 方法区（Method Area）

### 6.1 定义

方法区（Method Area）是线程共享的内存区域，用于存储：
- 已加载的**类信息**（类的元数据）
- **常量**
- **静态变量**
- **即时编译器编译后的代码缓存**

### 6.2 演进历史

| JDK 版本 | 方法区实现 | 说明 |
|----------|------------|------|
| JDK 7 及以前 | 永久代（PermGen） | 使用堆内存，但容易OOM |
| JDK 8 及以后 | 元空间（Metaspace） | 使用本地内存（Native Memory） |

### 6.3 永久代 vs 元空间

| 特性 | 永久代 | 元空间 |
|------|--------|--------|
| 位置 | JVM 堆内存 | 本地内存（操作系统内存） |
| 大小 | 固定，难以调整 | 可动态扩展 |
| OOM | 容易（-XX:PermSize） | 较少（-XX:MetaspaceSize） |
| 字符串常量 | 存储在永久代 | 存储在堆中（JDK 8） |

### 6.4 方法区存储内容

```
┌─────────────────────────────────────────┐
│              方法区                      │
├─────────────────────────────────────────┤
│  ┌─────────────────────────────────────┐│
│  │  类信息                              ││
│  │  - 类的完整结构（父类、接口、字段）  ││
│  │  - 方法信息（方法名、参数、返回类型） ││
│  │  - 字节码指令                        ││
│  └─────────────────────────────────────┘│
│  ┌─────────────────────────────────────┐│
│  │  运行时常量池                        ││
│  │  - 字面量（字符串、final常量）       ││
│  │  - 符号引用（类、字段、方法引用）    ││
│  └─────────────────────────────────────┘│
│  ┌─────────────────────────────────────┐│
│  │  静态变量                            ││
│  │  - 类变量（static 修饰）             ││
│  └─────────────────────────────────────┘│
│  ┌─────────────────────────────────────┐│
│  │  JIT 编译产物                        ││
│  │  - 热点代码编译后的本地机器码        ││
│  └─────────────────────────────────────┘│
└─────────────────────────────────────────┘
```

### 6.5 常见异常

- **OutOfMemoryError: Metaspace**：元空间不足，通常是类加载过多导致

### 6.6 面试提问

> **Q：JDK 8 为什么移除永久代？**
>
> A：原因有三：
> 1. 永久代大小固定，难以调优，容易 OOM
> 2. 字符串常量池和类元数据分离，便于管理
> 3. 合并 HotSpot 与 JRockit 的特性（JRockit 没有永久代）

> **Q：方法区存储的是对象吗？**
>
> A：不是。方法区存储的是类的元数据信息（类结构、字段、方法描述等），以及运行时常量池。对象实例存储在堆中。

## 7. 运行时常量池（Runtime Constant Pool）

### 7.1 定义

运行时常量池（Runtime Constant Pool）是方法区的一部分，用于存放：
- **字面量**：文本字符串、final 常量值
- **符号引用**：
  - 类和接口的全限定名
  - 字段的名称和描述符
  - 方法的名称和描述符

### 7.2 与 Class 文件常量池的区别

- **Class 文件常量池**：编译期确定，存储在 .class 文件中
- **运行时常量池**：运行时将 Class 文件常量池加载到内存，形成运行时常量池

### 7.3 String.intern() 方法

- `intern()` 方法会将字符串加入常量池
- JDK 6：常量池在永久代，intern() 复制字符串到永久代
- JDK 7+：常量池在堆中，intern() 只记录首次出现的引用

## 8. 对象创建过程

### 8.1 完整流程

```
┌─────────────────────────────────────────────────────────────────┐
│                    对象创建流程                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 检查加载                                                  │
│     │                                                         │
│     ▼                                                         │
│  2. 分配内存 ──────── 指针碰撞（Serial/ParNew）               │
│     │               或                                          │
│     │               空闲列表（CMS）                             │
│     ▼                                                         │
│  3. 初始化零值                                                 │
│     │                                                         │
│     ▼                                                         │
│  4. 设置对象头                                                 │
│     │                                                         │
│     ▼                                                         │
│  5. 执行 <init> 方法                                          │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 8.2 步骤详解

**Step 1: 检查加载**
- 检查 new 指令的参数是否能在常量池中定位到一个类的符号引用
- 检查该类是否已被加载、解析和初始化

**Step 2: 分配内存**
- 计算对象所需内存大小
- 分配方式：
  - **指针碰撞**：假设堆内存规整，使用过的内存放一边，空闲内存放另一边，中间有指针作为分界点。分配内存就是将指针向空闲区域移动对象大小距离
  - **空闲列表**：假设堆内存不规整，虚拟机维护一个记录可用内存的列表。分配内存时从列表中找一块足够大的空间分配

**Step 3: 初始化零值**
- 将分配到的内存空间（不包括对象头）都初始化为零值
- 保证对象的实例字段在 Java 代码中可以不赋初始值就直接使用

**Step 4: 设置对象头**
- 存储对象的元信息（哈希码、GC 分代年龄、锁状态标志等）
- 类型指针：指向方法区中该对象的类型元数据

**Step 5: 执行初始化方法**
- 执行 `<init>` 构造函数
- 按照程序员的意愿初始化对象

## 9. 对象的内存布局

### 9.1 整体结构

```
┌─────────────────────────────────────────────────────┐
│                 对象内存布局                         │
├─────────────────────────────────────────────────────┤
│  ┌───────────────────────────────────────────────┐ │
│  │              对象头 (Header)                   │ │
│  │  ┌────────────────┐  ┌────────────────────┐  │ │
│  │  │  Mark Word     │  │  类型指针 (Klass   │  │ │
│  │  │  (64位/32位)   │  │  Pointer)          │  │ │
│  │  └────────────────┘  └────────────────────┘  │ │
│  │  ┌────────────────────────────────────────┐ │ │
│  │  │  数组长度 (如果是数组对象)              │ │ │
│  │  └────────────────────────────────────────┘ │ │
│  └───────────────────────────────────────────────┘ │
│  ┌───────────────────────────────────────────────┐ │
│  │            实例数据 (Instance Data)          │ │
│  │  - 父类继承的实例变量                          │ │
│  │  - 本类定义的实例变量                          │ │
│  │  - 引用类型（4/8字节）                        │ │
│  │  - 基本类型（1/2/4/8字节）                    │ │
│  └───────────────────────────────────────────────┘ │
│  ┌───────────────────────────────────────────────┐ │
│  │            对齐填充 (Padding)                 │ │
│  │  - 对象起始地址必须是8字节的整数倍            │ │
│  │  - 填充是可选的，不一定存在                    │ │
│  └───────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────┘
```

### 9.2 对象头（Mark Word）

在 64 位 HotSpot 虚拟机中，Mark Word 占用 8 字节（64位），存储以下信息：

| 存储内容 | 标志位 | 说明 |
|----------|--------|------|
| 无状态 | 01 | 对象未锁定 |
| 指向互斥锁的指针 | 00 | 轻量级锁 |
| 指向互斥锁的指针 + 线程ID | 10 | 重量级锁 |
| 偏向线程ID + 偏向时间戳 | 01 | 偏向锁 |
| GC 标记 | 11 | 对象正在被 GC 回收 |

### 9.3 类型指针（Klass Pointer）

- 指向方法区中该对象的类元数据（Klass）
- JVM 通过这个指针确定对象是哪个类的实例
- 开启压缩指针（-XX:+UseCompressedOops）时占用4字节，否则占用8字节

### 9.4 实例数据

- 存储父类继承的字段和本类定义的字段
- 存储顺序受 JVM 参数 `-XX:FieldsAllocationStyle` 影响
- 默认顺序：long/double → int → short/char → byte/boolean → reference

### 9.5 对齐填充

- 不是必然存在，也没有特别含义
- 仅仅起占位符作用
- JVM 要求对象起始地址必须是8字节的整数倍

## 10. 对象的访问定位

### 10.1 两种方式

**方式一：句柄池访问**

```
┌─────────────────────────────────────────────────────────────────┐
│                         句柄池访问                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   栈帧中的 reference                                            │
│        │                                                       │
│        ▼                                                       │
│   ┌─────────────┐                                              │
│   │   句柄池     │                                               │
│   ├─────────────┤      ┌──────────────┐                       │
│   │ 指针A ──────┼─────→│  对象实例数据 │ (堆中)                │
│   ├─────────────┤      └──────────────┘                       │
│   │ 指针B ──────┼─────→│  对象类型数据 │ (方法区中)            │
│   └─────────────┘      └──────────────┘                       │
│                                                                 │
│   优点：对象移动时（GC时）只需要修改句柄中的指针                 │
│   缺点：增加一次指针访问                                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**方式二：直接指针访问**

```
┌─────────────────────────────────────────────────────────────────┐
│                       直接指针访问                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   栈帧中的 reference                                            │
│        │                                                       │
│        ▼                                                       │
│   ┌─────────────┐                                              │
│   │  对象实例    │      ┌──────────────┐                       │
│   ├─────────────┤      │ 对象类型指针  │←──┐                   │
│   │   数据...   │      └──────────────┘   │                   │
│   │             │                         │                   │
│   │             │      ┌──────────────┐   │                   │
│   │             │      │ 对象类型数据  │←──┘ (方法区中)        │
│   │             │      └──────────────┘                       │
│   └─────────────┘                                              │
│                                                                 │
│   优点：访问速度快（少一次指针访问）                             │
│   缺点：对象移动时需要修改栈帧中的引用                           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 10.2 HotSpot 选择

- **HotSpot 使用直接指针访问**
- 原因：速度快，减少一次指针访问

## 11. 实战问题汇总

### 11.1 常见面试问题

| 问题 | 答案要点 |
|------|----------|
| JVM 内存结构分为哪几部分？ | 程序计数器、虚拟机栈、本地方法栈、堆、方法区 |
| 哪些区域是线程私有的？ | 程序计数器、虚拟机栈、本地方法栈 |
| 哪些区域是线程共享的？ | 堆、方法区 |
| 栈帧包含哪些内容？ | 局部变量表、操作数栈、动态连接、返回地址 |
| 对象创建过程？ | 检查加载→分配内存→初始化零值→设置对象头→执行init |
| 对象头包含哪些信息？ | Mark Word（锁状态等）、类型指针、数组长度 |
| 句柄池和直接指针的区别？ | 句柄池稳定但慢，直接指针快但移动时需修改 |
| 方法区和元空间的区别？ | 位置不同、大小管理方式不同 |

### 11.2 常见异常

| 异常 | 发生区域 | 原因 |
|------|----------|------|
| StackOverflowError | 虚拟机栈 | 递归调用过深 |
| OutOfMemoryError | 虚拟机栈/本地方法栈 | 栈无法扩展 |
| OutOfMemoryError: Java heap space | 堆 | 对象过多，内存不足 |
| OutOfMemoryError: Metaspace | 方法区(元空间) | 类加载过多 |

## 12. 总结

### 核心要点

1. **线程私有**：程序计数器、虚拟机栈、本地方法栈
2. **线程共享**：堆、方法区
3. **对象分配**：堆中创建，栈中引用
4. **对象布局**：对象头 + 实例数据 + 对齐填充
5. **方法区演变**：JDK 7 永久代 → JDK 8 元空间

### 理解技巧

```
把 JVM 内存结构想象成一个工厂：

- 程序计数器：每个工位（线程）的任务清单
- 虚拟机栈：每个工人（线程）的工作台面
- 堆：产品仓库（所有产品都在这里）
- 方法区：产品说明书仓库（类信息）
- 运行时常量池：说明书中的常用术语表
```
