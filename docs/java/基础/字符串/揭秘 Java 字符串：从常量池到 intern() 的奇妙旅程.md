## 1. 字符串池（String Pool）
字符串池（也称字符串常量池，String Intern Pool）是 JVM 为了优化字符串存储和复用而引入的一块特殊内存区域。

+ 所有的 **字符串字面量** 和 **使用 **`**intern()**`** 方法的字符串**，都会存储在字符串池中。
+ 当两个字符串内容相同且来自字符串池时，它们的引用会相同，从而减少内存占用。

例子：

```plain
String a = "hello";
String b = "hello";
System.out.println(a == b); // true
```

这里的 `"hello"` 只在字符串池中存储一次，`a` 和 `b` 指向同一个对象。

---

## 2. Class 常量池
**Class 常量池** 是与 `.class` 文件对应的数据结构，主要包含以下信息：

+ 字面量（字符串、整型、浮点型等）
+ 符号引用（类名、方法名、字段名等）

当一个类被类加载器加载后，其 `.class` 文件中的 **Class 常量池** 会被加载到方法区（JDK 8 之后是 **元空间**），成为运行时常量池的一部分。

举个例子，以下代码中的 `"abc"` 就会存储在 `Test.class` 的 Class 常量池中：

```plain
public class Test {
    public static void main(String[] args) {
        String s = "abc";
    }
}
```

当类被加载时，`"abc"` 会被放入运行时常量池，并在需要时进入字符串池。

---

## 3. 字面量是什么时候存入字符串池的？
字符串字面量的存储时机有两步：

1. **编译期**：Java 编译器会把字面量写入 `.class` 文件的 Class 常量池。
2. **类加载期**：当类被加载时，Class 常量池中的字符串字面量会被解析并存放到 **字符串池** 中。

例子：

```plain
String x = "abc";
```

执行时流程是：

+ `"abc"` 在编译时就写入 `Test.class` 的常量池。
+ 当类加载时，JVM 会检查字符串池中是否存在 `"abc"`：
    - 如果不存在，创建并放入池中；
    - 如果已存在，直接复用。

---

## 4. `intern()` 方法
`intern()` 方法是字符串池机制的关键。

+ 调用 `s.intern()` 会检查字符串池中是否已经存在与 `s` 内容相等的字符串：
    - 如果存在，返回池中已有对象的引用；
    - 如果不存在，将当前字符串放入池中，并返回池中该对象的引用。

例子：

```plain
String s1 = new String("abc");
String s2 = s1.intern();
String s3 = "abc";

System.out.println(s1 == s2); // false
System.out.println(s2 == s3); // true
```

这里 `s1` 在堆中创建了一个新对象，而 `intern()` 返回的是字符串池中的 `"abc"` 引用。

---

## 5. String 有没有长度限制？
Java 中的 `String` 底层是由 `char[]`（JDK 8 之前）或 `byte[]`（JDK 9+，结合编码优化）实现的。

+ `String` 理论上的最大长度受 **数组长度限制**：
    - Java 数组的最大长度是 `Integer.MAX_VALUE`（约 2^31 - 1 ≈ 21 亿）。
    - 但 JVM 实际上会因内存限制而远小于理论值。

实际应用中：

+ **常见限制** 在几百 MB ~ 1GB 之间，取决于 JVM 堆大小。
+ 编译期的字符串字面量（写死在源码里的超长字符串）还受 **class 文件格式**限制，单个 UTF-8 常量最大为 **65535 字节**。

---

## 总结
+ **字符串池**：用来存储字面量和 `intern` 后的字符串，避免重复对象。
+ **Class 常量池**：class 文件中的常量表，存储字面量和符号引用。
+ **字面量存入时机**：编译期进常量池，类加载时进入字符串池。
+ **intern**：将字符串加入池，返回池中引用。
+ **长度限制**：受数组长度（2^31 - 1）和 class 文件格式（65535 bytes）的双重限制。
