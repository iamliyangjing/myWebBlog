# BMAD 方法框架概述

BMAD（Business Model And Development）是一个系统化的产品开发方法论，通过AI代理协作促进高效的产品设计和软件开发。该方法论提供多种适应不同规模和复杂度的开发流程。

## 三个核心流程（以表格形式呈现）

| 流程名称 | 适用场景 | 核心目标 | 关键活动 | 主要产出物 |
|----------|----------|----------|----------|------------|
| Quick Flow | 简单快速的任务（小需求/Bug修复） | 快速完成小型开发任务 | 需求定义 → 技术规格制定 → 任务拆分 → 编码实现 → 代码评审 | tech-spec.md 技术规格书<br/>Story 文件<br/>可直接使用的代码 |
| BMAD Method | 中小型任务（中大型产品开发） | 完整的端到端产品开发 | 需求分析 → 产品规划 → 架构设计 → 任务拆分 → 迭代开发 | PRD 文档<br/>Architecture 文档<br/>Epic 和 Story 文件<br/>完整的应用代码 |
| Enterprise | 企业级任务（分布式系统/合规性平台） | 企业级系统的安全、合规开发 | 业务分析 → 合规需求 → 安全架构 → 运维设计 → 企业级开发 | 企业级PRD<br/>安全设计文档<br/>运维设计文档<br/>合规代码及测试用例 |

## 各流程详细介绍

### Quick Flow（简单快速的任务）

| 步骤 | 所属阶段 | 调用代理 | 核心命令 | 操作说明 | 核心产出物 | 备注 |
|------|----------|----------|----------|----------|------------|------|
| 1 | 初始化阶段（必需） | Analyst 分析师 | *workflow-init | 输入：存量 / 全新 Java+Web+H5 项目，小需求 / Bug 修复，简单复杂度，确认选择「Quick Flow」轨道 | bmm-workflow-status.yaml 项目进度跟踪文件 | 初始化项目匹配类型，必须第一步执行，全程中文输入即可 |
| 2 | 规划阶段（必需） | PM 产品经理 | *tech-spec | 输入：需求细节 + 技术约束 + 验收标准，例「修复 Java 分页越界 Bug，Mybatis-Plus 实现，返回最后一页 + 提示文案；开发单个 Vue3 表单组件」 | tech-spec.md 技术规格书 | Quick Flow 核心文档，替代 PRD + 架构文档，所有开发的唯一依据，必做 |
| 3 | 实现阶段（必需） | PM 产品经理 | *create-epics-and-stories | 无需额外输入，AI 自动读取技术规格书拆分任务 | _bmad-output/epics/ 拆分的 Epic 大功能 + Story 最小开发任务 | 自动拆分任务粒度，Story 为 10-30 分钟可完成的最小单元 |
| 4 | 实现阶段（必需） | SM 迭代经理 | *create-story | 输入：要开发的任务名称，例「修复分页查询 Service 逻辑、开发 H5 登录页面」 | 单个 Story 详细开发文档 | 提取任务完整技术要求，聚焦开发目标，无需额外补充需求 |
| 5 | 实现阶段（必需） | DEV 开发工程师 | *dev-story | 输入：代码风格约束，例「贴合项目 Java 分层结构，前端封装 axios，H5 做 rem 自适应布局」 | Java 后端代码 + Web 前端组件 + H5 页面代码 + 单元测试代码 | 核心开发环节，生成的代码直接粘贴微调即可使用 |
| 6 | 实现阶段（必需） | DEV 开发工程师 | *code-review | 粘贴生成 / 手写的代码 | 代码质量评审报告 + 优化建议 + 修复后代码 | 校验语法错误、空指针、SQL 注入、代码风格，必做保质量，避免低级 Bug |
| 7 | 实现阶段（可选） | TEA 测试工程师 | *automate | 无需额外输入，AI 自动生成 | 单元测试用例、接口测试用例 | Java 项目刚需，覆盖边界场景，提升代码健壮性 |
| 8 | 实现阶段（可选） | SM 迭代经理 | *retrospective | 输入：本次开发问题 / 优化点，例「测试用例覆盖不足，下次补充边界场景」 | 迭代复盘报告 | 完成所有任务后执行，总结问题优化流程，个人开发也建议做 |
| 9 | 全流程通用 | Any 任意代理 | *workflow-status | 输入：查询项目进度 | 当前阶段 + 下一步操作指引 | 万能指令，忘记下一步做什么时调用任意代理执行即可，必备！ |

### BMAD Method（中小型任务）

| 步骤 | 所属阶段 | 调用代理 | 核心命令 | 操作说明 | 核心产出物 | 备注 |
|------|----------|----------|----------|----------|------------|------|
| 1 | 分析阶段（可选，建议做） | Analyst 分析师 | *workflow-init | 输入：存量 / 全新 Java+Web+H5 全栈项目，中大型产品开发，中高复杂度，确认选「BMAD Method」轨道 | bmm-workflow-status.yaml 项目进度跟踪文件 | 初始化项目匹配类型，必须第一步执行 |
| 2 | 分析阶段（可选，建议做） | Analyst 分析师 | *brainstorm-project | 输入：项目核心定位 + 功能，例「校友管理系统，实现用户登录 / 校友信息管理 / 活动发布 / H5 端查询」 | 头脑风暴文档、核心功能清单 | 梳理模糊需求明确边界，减少后期返工 |
| 3 | 分析阶段（可选） | Analyst 分析师 | *product-brief | 无需额外输入，AI 自动生成 | product-brief.md 产品简报 | 极简产品说明，衔接需求与正式 PRD |
| 4 | 规划阶段（必需） | PM 产品经理 | *prd | 输入：完整需求 + 用户场景 + 验收标准，例「实现用户增删改查、校友分页查询、活动审核，接口统一 JSON 格式，H5 适配移动端」 | PRD.md 完整产品需求文档 | 核心文档，后续开发唯一需求依据，必做 |
| 5 | 方案设计阶段（必需） | Architect 架构师 | *create-architecture | 输入：技术栈约束，例「后端 Java+SpringBoot3+Mybatis-Plus+MySQL；前端 Vue3+ElementPlus；H5 HTML5+rem 自适应」 | architecture.md 完整架构设计文档 | BMAD Method 核心环节，含库表 / 接口 / 部署方案，区别 Quick Flow 的关键，必做 |
| 6 | 方案设计阶段（可选） | UX Designer 设计师 | *ux-design | 输入：页面需求，例「Web 管理后台布局，H5 简洁查询页，适配手机 / 平板」 | Web/H5 原型图、交互规范、配色方案 | 适配你的 Web+H5 开发，直接参考写前端代码 |
| 7 | 方案设计阶段（必需） | Architect 架构师 | *implementation-readiness | 无需额外输入，AI 自动校验 | 规划文档一致性校验报告 | 校验 PRD 与架构无冲突、需求可落地，避免开发后返工，必做 |
| 8 | 实现阶段（必需） | PM 产品经理 | *create-epics-and-stories | 无需额外输入，AI 自动读取 PRD + 架构文档 | _bmad-output/epics/ 模块拆分的 Epic 大功能 + Story 最小开发任务 | Epic = 大模块，Story = 单个开发任务，自动拆分粒度刚好 |
| 9 | 实现阶段（必需） | SM 迭代经理 | *sprint-planning | 输入：迭代周期 + 优先级，例「Sprint1，优先开发用户模块，周期 7 天」 | sprint-status.yaml 迭代进度跟踪文件 | 规划任务优先级，个人 / 团队开发均适用 |
| 10 | 实现阶段（必需） | SM 迭代经理 | *create-story | 输入：开发任务名称，例「实现用户登录接口 / 开发校友列表 H5 页」 | 单个 Story 详细开发文档 | 提取任务完整需求，聚焦开发目标 |

## BMAD基本安装与使用

### 安装流程
```bash
npx bmad-method@alpha install
```

- 基本都选择 y。
- IDEA环境可以多选，建议安装的时候选一个IDEA环境最好。
- 不要创建额外的文件夹。

### 基本使用流程
1. 安装完成后，打开第一个AI窗口直接输入 `/Analyst` 代理回车
2. 输出菜单后在AI窗口输入 `*workflow-init` 回车或者在命令后面输入你想说的项目描述
3. 后面就按正常的工作流程进行，取舍流程看自己的业务和功能进度

### 核心命令汇总

| 命令 | 代理 | 描述 |
|------|------|------|
| *workflow-init | Analyst 分析师 | 初始化新项目 |
| *workflow-status | Any | 查看项目进度和下一步操作 |
| *prd | PM 产品经理 | 生成产品需求文档 |
| *create-architecture | Architect 架构师 | 生成架构设计文档 |
| *create-epics-and-stories | PM | 将产品需求文档拆解为大功能模块（Epic）和开发任务（Story） |
| *implementation-readiness | Architect 架构师 | 验证规划文档的一致性与完整性，确认是否具备开发条件 |
| *sprint-planning | SM | 初始化迭代规划，生成迭代进度跟踪文件 |
| *create-story | SM | 创建单个开发任务（Story）的详细文件 |
| *dev-story | DEV | 实现单个开发任务（Story）的代码编写 |
| *code-review | DEV | 对已实现的代码进行质量评审 |

**注意**: 每个工作流都要新建一个窗口开始任务。
