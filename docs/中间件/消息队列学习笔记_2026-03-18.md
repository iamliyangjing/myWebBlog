# 消息队列学习笔记 Day52

> 日期：2026-03-18

## 什么是消息队列？

**消息队列**就是一种"排队"机制。就像餐馆叫号一样：
- 客人点餐（**生产者**发送消息）
- 拿到号码等待叫号（消息进入队列）
- 服务员叫号取餐（**消费者**处理消息）

## 为什么要用消息队列？

1. **解耦**：系统之间不直接调用，通过队列通信，一个模块出问题不影响其他模块
2. **异步**：非实时任务可以慢慢处理，提高系统响应速度
3. **削峰**：流量高峰时消息堆积，等高峰期过了再慢慢处理
4. **缓冲**：平衡生产者和消费者的处理速度差异

## 主流消息队列对比

| 特性 | Kafka | RabbitMQ | RocketMQ |
|------|-------|----------|----------|
| **语言** | Scala/Java | Erlang | Java |

| **适用场景** | 大数据日志、实时流处理 | 企业级应用、复杂路由 | 电商、金融、订单系统 |

## Kafka 核心概念

### 基础概念
- **Topic（主题）**：消息的分类，类似文件夹
- **Partition（分区）**：Topic 物理上的分片，提高并行度
- **Broker**：Kafka 服务节点
- **Producer**：生产者，负责发消息
- **Consumer**：消费者，负责收消息
- **Consumer Group**：消费者组，同一组内消息只被消费一次

### 工作流程
```
Producer → Broker(Topic/Partition) → Consumer Group
```

### 特点
- **高吞吐量**：靠顺序写磁盘 + 零拷贝技术
- **分布式**：支持分区副本容灾
- **消息持久化**：消息落盘，可重复消费
- **Pull模式**：消费者主动拉取消息

---

## RabbitMQ 核心概念

### 基础概念
- **Exchange（交换机）**：消息路由规则
- **Queue（队列）**：消息存储容器
- **Binding（绑定）**：交换机和队列的关联关系
- **Routing Key（路由键）**：消息匹配规则

### 消息流转
```
Producer → Exchange → Binding → Queue → Consumer
```

### 交换机类型
1. **Direct**：完全匹配路由键
2. **Fanout**：广播到所有队列
3. **Topic**：模糊匹配（* 代替一个词，# 代替零或多个词）
4. **Headers**：根据消息头属性匹配

### 特点
- **功能丰富**：支持多种协议（AMQP、MQTT、STOMP）
- **灵活的路由**：四种交换机类型
- **消息确认**：支持 ACK 机制
- **轻量级**：Erlang 实现，消息转发快

## RocketMQ 核心概念

### 基础概念
- **Topic**：消息主题
- **Tag**：消息标签，用于二级分类
- **Queue**：队列（Kafka 是 Partition，RocketMQ 叫 Queue）
- **Message**：消息实体
- **Producer**：生产者
- **Consumer**：消费者
- **NameServer**：注册中心，类似 Zookeeper
- **Broker**：消息存储节点

### 消息类型
1. **普通消息**：最基础的消息类型
2. **顺序消息**：全局顺序或分区顺序
3. **事务消息**：支持分布式事务（半消息+回查机制）
4. **延迟消息**：定时发送

### 特点
- **分布式事务**：阿里巴巴开源，支持 TCC 事务
- **顺序消息**：保证消息顺序（Kafka 也支持但不如 RocketMQ 灵活）
- **延迟消息**：支持指定延迟级别
- **消费模式**：支持广播和集群消费
- **Java 开发**：纯 Java 实现，方便定制

---

## 三种 MQ 如何选型？

### 推荐 Kafka 的场景
- 日志收集、大数据实时计算
- 需要极高吞吐量
- 消息可以短暂丢失（但不能重复）

### 推荐 RabbitMQ 的场景
- 中小型项目，功能需求多样
- 需要复杂的路由逻辑
- 对消息可靠性要求高

### 推荐 RocketMQ 的场景
- 电商、订单、金融类系统
- 需要分布式事务
- 需要顺序消息和延迟消息
- Java 技术栈为主

---

## 今日总结

消息队列是现代分布式系统的"粘合剂"，三种主流 MQ 各有特色：
- **Kafka**：高吞吐，适合大数据场景
- **RabbitMQ**：功能丰富，适合企业应用
- **RocketMQ**：事务强大，适合电商金融

根据业务场景选择合适的 MQ，才能发挥最大价值。
