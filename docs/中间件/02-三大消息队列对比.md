# 三大消息队列对比：Kafka vs RabbitMQ vs RocketMQ

> 📅 2026-03-16 | 分类：消息队列对比

---

## 🎯 开头先看结论

| 场景 | 推荐选择 |
|------|----------|
| 日志收集、大数据 | **Kafka** |
| 业务系统、灵活路由 | **RabbitMQ** |
| 金融、电商、高可靠 | **RocketMQ** |

---

## 🐰 RabbitMQ - 最"传统"的消息队列

### 是什么？
RabbitMQ 是最早流行的消息中间件之一，基于 **AMQP 协议**。

### 核心概念（重要！）

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  Producer   │────▶│   Exchange  │────▶│   Queue     │────▶│  Consumer   │
└─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘
       │                   │                   │
       │                   │                   │
    发送消息           交换机（路由）          队列（存储）
```

### 四种交换机类型

| 类型 | 作用 |
|------|------|
| **Direct** | 精确匹配，完全相等才投递 |
| **Fanout** | 广播，复制到所有队列 |
| **Topic** | 模糊匹配，`order.*` 或 `order.#` |
| **Headers** | 根据消息头属性匹配 |

### 举个例子 🌰

```
场景：订单处理

生产者发送订单消息 → Exchange(路由键: order.created)
                          │
              ┌───────────┼───────────┐
              ▼           ▼           ▼
         短信队列     物流队列    库存队列
         (绑定order.#) (绑定order.logistics) (绑定order.inventory)
```

### 优点
- ✅ 支持灵活的路由规则
- ✅ 社区成熟，文档丰富
- ✅ 支持多语言客户端

### 缺点
- ⚠️ 吞吐量相对较低
- ⚠️ 集群扩展复杂

---

## 🔥 Kafka - 大数据时代的"王者"

### 是什么？
Kafka 最初由 LinkedIn 开发，主打**高吞吐**，专为日志收集和流处理设计。

### 核心概念

```
┌─────────────────────────────────────────────────────┐
│                    Kafka 集群                        │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐             │
│  │ Broker1 │  │ Broker2 │  │ Broker3 │  ...        │
│  └────┬────┘  └────┬────┘  └────┬────┘             │
│       │            │            │                    │
│       ▼            ▼            ▼                    │
│  ┌─────────────────────────────────────┐            │
│  │           Topic: order-log          │            │
│  │  [Partition0] [Partition1] [Part2]  │            │
│  └─────────────────────────────────────┘            │
└─────────────────────────────────────────────────────┘
```

### 关键概念

| 概念 | 解释 |
|------|------|
| **Topic** | 主题，消息的分类 |
| **Partition** | 分区，物理上的"分片" |
| **Replica** | 副本，保证高可用 |
| **Offset** | 偏移量，消费者读取位置 |
| **Consumer Group** | 消费组，同组消息不重复 |

### 为什么这么快？

1. **顺序写入**：磁盘顺序IO，比随机IO快很多
2. **零拷贝**：利用 Linux 的 sendfile 技术
3. **批量处理**：多条消息一起发送
4. **压缩传输**：支持 gzip、snappy 压缩

### 举个例子 🌰

```
场景：用户行为日志收集

APP → Kafka(Topic: user行为) → 多个消费者
                                    │
                    ┌───────────────┼───────────────┐
                    ▼               ▼               ▼
               实时计算         数据仓库         监控报警
```

### 优点
- ✅ 百万级消息/秒，吞吐量顶级
- ✅ 分布式天生支持水平扩展
- ✅ 消息持久化，容错性强

### 缺点
- ⚠️ 消费顺序不保证（单分区内有序）
- ⚠️ 重复消费需要业务方处理

---

## 🚀 RocketMQ - 阿里巴巴的"亲儿子"

### 是什么？
RocketMQ 是阿里巴巴开源的分布式消息中间件，专注**金融级可靠性**。

### 核心概念（和Kafka类似但有区别）

```
┌─────────────────────────────────────────────────────┐
│                   RocketMQ 集群                      │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐             │
│  │ NameServer│ │NameServer│ │NameServer│ (注册中心)  │
│  └────┬────┘  └────┬────┘  └────┬────┘             │
│       │            │            │                    │
│       ▼            ▼            ▼                    │
│  ┌─────────────────────────────────────┐            │
│  │     Broker (Master + Slave)         │            │
│  │  Producer ←→ NameServer ←→ Consumer│            │
│  └─────────────────────────────────────┘            │
└─────────────────────────────────────────────────────┘
```

### 特色功能

| 功能 | 说明 |
|------|------|
| **顺序消息** | 全局顺序、分区顺序都能保证 |
| **事务消息** | 类似分布式事务，两阶段提交 |
| **延迟消息** | 支持定时发送（如下单15分钟后发短信） |
| **消息回溯** | 可以重新消费历史消息 |

### 举个例子 🌰

```
场景：金融交易

1. 用户转账 1000 元
2. 发送"转账消息"到 RocketMQ（带事务）
3. 扣款成功 → 提交消息
4. 扣款失败 → 回滚消息
5. 消费者收到确定性的"转账成功"消息
```

### 对比 Kafka

| 特性 | Kafka | RocketMQ |
|------|-------|----------|
| 顺序消息 | 单分区保证 | 全局/分区都支持 |
| 事务消息 | 支持但不完善 | 完整事务支持 |
| 延迟消息 | 不支持 | 支持 |
| 消息回溯 | 支持 | 支持 |

### 优点
- ✅ 金融级可靠性
- ✅ 支持事务消息
- ✅ 顺序消息能力强
- ✅ 阿里大规模验证

### 缺点
- ⚠️ 社区没有 Kafka 活跃
- ⚠️ 生态略弱

## 📊 总结对比

```
                    吞吐量     可靠性     易用性     适用场景
                   ─────────────────────────────────────────────────
    Kafka         ★★★★★    ★★★★☆    ★★★★☆    日志、大数据
    RabbitMQ      ★★★☆☆    ★★★★★    ★★★★★    业务系统、路由
    RocketMQ      ★★★★☆    ★★★★★    ★★★★☆    金融、电商
```

### 选型建议

- **日志收集 + 实时流处理** → Kafka
- **企业业务系统 + 复杂路由** → RabbitMQ  
- **金融/电商 + 高可靠 + 事务** → RocketMQ
